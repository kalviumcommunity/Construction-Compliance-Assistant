# SiteSafe Uniform Chunk Metadata & Source Traceability Report

## Systems Architecture Overview

In regulatory compliance RAG applications ("SiteSafe"), every answer generated by the LLM must be strictly verifiable against statutory source documents. When documents are chunked, raw text fragments lose their origin unless they carry **uniform, machine-readable metadata**.

Uniform metadata enables two critical production capabilities:
1. **Vector DB Pre-Filtering**: Filtering search spaces by `jurisdiction`, `trade`, or `doc_type` prior to vector similarity calculation.
2. **Deterministic Source Traceability**: Using global character start/end offsets (`char_start`, `char_end`) to perform exact reverse lookups against raw source files.

This report documents the Pydantic v2 data model, automated section tagging, and reverse lookup verification suite implemented in [`backend/metadata_tagger.py`](file:///f:/desk/RAG/backend/metadata_tagger.py).

## 1. Uniform Pydantic v2 Data Schema (Tasks 1 & 3)

```python
class ChunkMetadata(BaseModel):
    source_doc_id: str     # Filename or document identifier (e.g. "IBC_2021_Fire_Safety.pdf")
    doc_type: str          # Category ("building_code", "project_spec", "inspection_log")
    jurisdiction: str      # Jurisdiction ("California", "NYC", "National")
    trade: str             # Trade discipline ("Fire Safety", "Structural", "QA/QC")
    section_clause: str    # Extracted legal clause / division ("Section 705.8", "Division 03 30 00")
    page_number: int       # Source page number
    chunk_index: int       # 0-indexed position within parent document
    total_chunks: int      # Total chunks produced from parent
    char_start: int        # Global start character offset in original document
    char_end: int          # Global end character offset in original document

class TaggedChunk(BaseModel):
    chunk_id: str          # Deterministic ID: "{source_doc_id}_chunk_{chunk_index}"
    content: str           # Chunk text payload
    metadata: ChunkMetadata
```
